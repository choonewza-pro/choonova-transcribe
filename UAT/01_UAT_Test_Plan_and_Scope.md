# UAT Test Plan / Scope Definition
**Project:** ChooNova Transcribe
**Version:** 1.0

## 1. วัตถุประสงค์ (Objective)
เอกสารฉบับนี้จัดทำขึ้นเพื่อกำหนดขอบเขตและแผนการทดสอบการยอมรับของผู้ใช้ (User Acceptance Testing - UAT) สำหรับระบบ **ChooNova Transcribe** เพื่อให้มั่นใจว่าระบบสามารถทำงานได้ตามความต้องการทางธุรกิจ (Business Requirements) และพร้อมสำหรับการเปิดใช้งานจริง

## 2. ขอบเขตการทดสอบ (In-Scope)
การทดสอบในรอบนี้จะครอบคลุมฟีเจอร์และโมดูลหลัก ดังต่อไปนี้:

1.  **Web UI (Dashboard):**
    *   การใช้งานหน้าเว็บไซต์ในการอัปโหลดไฟล์เสียง/วิดีโอ เพื่อถอดข้อความ
    *   การแสดงผลข้อความที่ถอดได้ ความรวดเร็ว และความถูกต้องของ UI
2.  **Transcription Engine (ระบบถอดเสียง):**
    *   การถอดเสียงภาษาไทย (Typhoon ASR) แบบอัปโหลดไฟล์ (Batch)
    *   การถอดเสียงภาษาอังกฤษ (faster-whisper) แบบอัปโหลดไฟล์
    *   การถอดเสียงแบบเรียลไทม์ (Real-time Transcription) ผ่านไมโครโฟนหน้าเว็บ
3.  **Video Compression (การบีบอัดวิดีโอ):**
    *   ความสามารถในการบีบอัดไฟล์วิดีโอและดาวน์โหลดไฟล์ที่ขนาดเล็กลง
4.  **System Settings & Resource Management (การจัดการทรัพยากร):**
    *   การตั้งค่าโหมดการจัดการหน่วยความจำ (VRAM Mode) ทั้งแบบ `always` (โหลดค้างไว้) และ `idle` (คืนหน่วยความจำเมื่อไม่ใช้งาน)
5.  **API Security (ความปลอดภัยของ API):**
    *   การตรวจสอบสิทธิ์การเข้าถึง API ทุกเส้นทาง (`/v1/*`) ด้วย `x-api-key`

## 3. สิ่งที่อยู่นอกขอบเขต (Out of Scope)
การทดสอบต่อไปนี้จะ**ไม่รวมอยู่**ในรอบ UAT นี้ (แต่อาจจะมีการทดสอบในรอบอื่นๆ เช่น SIT, NFR):

1.  **Load Testing / Performance Testing:** การทดสอบยิง Request จำนวนมหาศาลพร้อมๆ กันเพื่อหาขีดจำกัดของระบบ
2.  **Security Penetration Testing:** การทดสอบเจาะระบบขั้นสูง หรือหาช่องโหว่ระดับเซิร์ฟเวอร์
3.  **Infrastructure Setup:** การทดสอบการตั้งค่า Network, การรัน Docker Network Command หรือการติดตั้ง Hardware GPU (ถือว่าสภาพแวดล้อมถูกจัดเตรียมสมบูรณ์แล้ว)

## 4. ผู้เข้าร่วมการทดสอบ (Test Participants)
*   **Business Users (ผู้ใช้งานทั่วไป):** ทดสอบความถูกต้องของระบบผ่านหน้า Web UI และการใช้งานแบบเรียลไทม์
*   **Developer / System Admin:** ทดสอบการเรียกใช้ API, ตรวจสอบการจัดการหน่วยความจำ (VRAM), และตรวจสอบระบบเมื่อเกิดความผิดพลาด (Watchdog/Resilience)

## 5. สภาพแวดล้อมที่ใช้ในการทดสอบ (Test Environment)
*   ระบบได้รับการ Deploy ผ่าน Docker (`docker compose up -d`) เรียบร้อยแล้ว
*   ระบบทำงานบนพอร์ต `8830`
*   มีการตั้งค่า API Key ล่วงหน้าสำหรับการทดสอบฝั่ง API
*   เข้าใช้งานผ่านเบราว์เซอร์มาตรฐาน (เช่น Google Chrome, Safari, Edge) แนะนำให้อัปเดตเป็นเวอร์ชันล่าสุดเพื่อรองรับ WebSockets และ Microphone API
